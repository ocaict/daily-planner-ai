# DAILY PLANNER AI
## Stage 0 — Project Foundation & Architecture

You are the lead developer building a production-ready Android application called **Daily Planner AI**.

The application will be built using:

- Ionic
- Capacitor
- HTML
- CSS
- JavaScript
- SQLite/local persistent storage
- Android native capabilities through Capacitor
- Groq as the initial AI provider

The application is an offline-first daily planning assistant. AI is an intelligent interface to the user's planner data; it is NOT the application's source of truth.

---

# IMPORTANT DEVELOPMENT RULE

This is **Stage 0 only**.

Do NOT implement the following yet:

- AI chat
- Groq API integration
- Voice assistant
- Speech-to-text
- Text-to-speech
- Daily planning algorithms
- Background notifications
- Calendar functionality
- Authentication
- Cloud synchronization
- Payments
- Subscription system

We will implement these in later stages.

Your job in this stage is to create a clean, maintainable, production-oriented foundation.

---

# 1. First inspect the environment

Before changing anything:

1. Inspect the existing project directory.
2. Determine whether an Ionic/Capacitor project already exists.
3. Inspect package.json and existing dependencies.
4. Inspect the current source structure.
5. Determine the installed Node.js/npm versions.
6. Determine whether Android Studio/Android SDK/Gradle tooling is available.
7. Do not delete existing user code unless absolutely necessary.
8. If the project does not exist, initialize the appropriate Ionic project.

Do not blindly recreate an existing project.

---

# 2. Technology decisions

Use a simple architecture that an AI coding agent can maintain easily.

Prefer:

- Ionic UI components where useful
- Plain JavaScript rather than introducing unnecessary frameworks
- CSS variables for theming
- ES modules
- Capacitor for native functionality
- SQLite for persistent application data
- Service/repository separation
- Small focused modules

Avoid unnecessary dependencies.

Do not add a library simply because it is convenient if the same functionality can be implemented cleanly with existing platform/Ionic capabilities.

---

# 3. Create the application structure

Establish a structure similar to:

src/
  components/
  pages/
  services/
  repositories/
  database/
  models/
  utils/
  styles/
  config/

Create additional directories only when justified.

The exact structure may be adjusted to fit the Ionic project generated by the chosen Ionic version, but maintain the same architectural separation.

---

# 4. Architecture principles

Use this logical architecture:

UI
↓
Application Services
↓
Repositories
↓
Local Database

AI will later connect through:

UI
↓
AI Service
↓
AI Provider
↓
Groq

The UI must NOT directly communicate with SQLite.

The UI must NOT directly call Groq.

The UI must NOT contain business logic that belongs in services.

Repositories are responsible for data access.

Services are responsible for application/business operations.

---

# 5. Create core services

Create placeholders/interfaces/modules for:

- TaskService
- PlannerService
- NotificationService
- AIService
- VoiceService
- SettingsService

Only create the architectural interfaces/placeholders at this stage.

Do not implement their future functionality yet.

AIService must be designed so that the AI provider can later be replaced.

For example:

AIService
  ↓
AIProvider
  ↓
GroqProvider

Do not hard-code Groq throughout the application.

---

# 6. Database foundation

Set up the SQLite architecture, but keep the schema minimal at this stage.

Prepare the database layer for future entities such as:

- tasks
- categories
- reminders
- daily_plans
- preferences
- ai_conversations

Do not implement unnecessary tables yet.

Create a database initialization/migration mechanism.

Database migrations must be versioned.

Example concept:

Database version 1
→ future version 2
→ future version 3

Never assume the database is empty on application startup.

The application must be able to safely upgrade an existing database.

---

# 7. Configuration

Create a central configuration system.

Prepare for:

- application environment
- API configuration
- feature flags
- development/production mode

IMPORTANT:

Never hard-code a Groq API key into JavaScript, HTML, CSS, or any file that will be packaged into the Android APK.

The eventual AI architecture must account for this security issue.

For Stage 0, simply create the configuration architecture.

Define variables for:

- secondary

- border

Create the main application navigation.

The planned primary sections are:

Add Settings through an appropriate menu/button rather than necessarily adding it to the bottom navigation.

- Empty state

Calendar

- Placeholder explaining that AI will be enabled in a later stage

Settings

---

# 10. UI states

Establish reusable patterns for:

- Loading
- Empty
- Error
- Success
- Confirmation
- Offline

These should be reusable rather than duplicated across every page.

---

# 11. Offline-first principle

The application must remain usable when there is no internet connection.

Design the architecture so that:

Core application:
- Does not depend on internet
- Does not depend on AI
- Does not require a backend

Later AI features may require internet, but the planner itself must continue functioning offline.

---

# 12. Error handling

Create a consistent error-handling strategy.

Requirements:

- Do not expose raw technical errors to users.
- Log useful development information.
- Show human-readable messages.
- Handle database failures gracefully.
- Handle missing permissions gracefully.
- Do not allow one failed service to crash the entire application.

Create reusable utilities if appropriate.

---

# 13. Android readiness

Make sure the project can:

1. Build the web application.
2. Sync with Capacitor.
3. Open/build the Android project.
4. Run on an Android device/emulator if the environment supports it.

Do not implement background services yet.

Do not implement microphone permissions yet.

Do not implement notification permissions yet.

Those belong to later stages.
